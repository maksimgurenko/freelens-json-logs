# Compact-view Back and input contracts

Researched 2026-10-24 for [research ticket #23](https://github.com/maksimgurenko/freelens-json-logs/issues/23), part of [map #20](https://github.com/maksimgurenko/freelens-json-logs/issues/20). This is source research and a recommendation for the UX decisions, not an accepted product specification or a runtime verification report.

The supported, conservative direction is an extension-owned local Back action and focus-scoped DOM shortcuts. Preserve Freelens's native Back accelerator. Treat native mouse Back as an unresolved integration requirement: a browser prototype can demonstrate the desired transition but cannot establish its delivery inside Freelens. The evidence and remaining gates follow.

## Back has several distinct delivery paths

| Layer | Source fact | Consequence / limit |
| --- | --- | --- |
| DOM mouse input | The pointer specification identifies mouse button `3` as X1/Back and `4` as X2/Forward; `button` identifies a button transition, while `buttons` is a bitmask. `auxclick` describes non-primary activation. [Pointer Events, mouse buttons and auxclick](https://w3c.github.io/pointerevents/#dom-mouseevent-button), [UI Events algorithms, 2024-02-08](https://w3c.github.io/uievents/event-algo.html#mouseevent-calculate-button) | These values describe events **if delivered**. They do not establish that an OS/driver/Electron combination delivers a particular mouse gesture to this extension. `button === 3` is not the same test as `buttons === 3`. |
| Electron native command | Electron documents `BrowserWindow` **`app-command`** on **Windows and Linux**, including `browser-backward`/`browser-forward`; some Windows mouse Back buttons use this path. The example explicitly performs navigation in an app callback. [Electron 41.10.0 BrowserWindow](https://github.com/electron/electron/blob/v41.10.0/docs/api/browser-window.md#event-app-command-windows-linux) | This is a **main-process native-window event**, not a DOM event in the cluster page. Its contract does not promise an equivalent DOM `auxclick`, or that DOM `preventDefault()` cancels the native command. The API is not documented for macOS. |
| Windows message | `WM_APPCOMMAND` identifies browser Back and the originating device class, including mouse. [Microsoft, updated 2025-07-14](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-appcommand) | A primary OS reason not to equate mouse hardware with DOM events. This does not prove Freelens's actual behavior on Windows. |
| Pinned host native handling | A search of the 1.10.3 upstream packages and installed core main/renderer bundles found **no `app-command` or `browser-backward` handler**. Its explicit Back paths use `navigationHistory.goBack()`. [Host window actions](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/main/ipc/window.ts#L11-L24), [host Back menu](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/features/application-menu/main/menu-items/view/go-back/go-back-menu-item.injectable.ts#L14-L27) | **Search observation, not proof of no navigation:** Chromium defaults, Electron native implementation, drivers and other extensions remain outside that negative search. Do not promise native mouse Back works, is ignored, or is interceptable. |
| Browser history | `history.back()` traverses overall session history; `pushState()` creates an entry. During relevant traversal, the HTML algorithm restores history state before firing `popstate` at the affected document's Window. [HTML History interface](https://html.spec.whatwg.org/multipage/nav-history-apis.html#the-history-interface), [history-step application](https://html.spec.whatwg.org/multipage/browsing-the-web.html#apply-the-history-step) | `popstate` is an after-traversal notification, not a cancellable “Back was pressed” command. It can also result from script or Forward. A local Profiles boolean has no corresponding browser entry. |
| Cluster iframe | Freelens creates a real `iframe` for each cluster; its URL prefixes the root host with the cluster ID. The different host makes it a different origin under HTML's origin definition. [Frame creation](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/renderer/components/cluster-manager/cluster-frame-handler.ts#L50-L77), [URL construction](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/common/utils/cluster-id-url-parsing.ts#L29-L36), [HTML origins](https://html.spec.whatwg.org/multipage/browsers.html#concept-origin) | A listener inside the extension observes its own document event path. It does not automatically receive root-frame DOM input or own the native BrowserWindow. Cross-origin parent DOM access is restricted; a relay needs an explicit, correctly scoped contract. |

**Proposal:** keep local Profiles, draft and confirmation transitions in extension state, with one local Back command. Do not add dummy history entries, overwrite host history state, patch the native Back menu or use `popstate` to push the user forward again. The host already owns browser history through `createBrowserHistory()` and route pushes; public navigation helpers expose destination navigation, not a hook to intercept every Back request. This risk assessment is an inference from those implementations, not a claim that standard `pushState()` is itself unsupported. [Host history owner](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/routing/src/history.injectable.ts#L7-L20), [route push/replace](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/renderer/routes/navigate-to-url.injectable.ts#L19-L35)

If mouse Back is required to close Profiles before leaving Readable logs, retain that requirement as a **native delivery gate**. First determine whether the real host delivers DOM events, an app-command, history traversal, several of these, or none. Only then choose a DOM handler or a narrow main/renderer relay; neither is established by this report. A relay must target the owning active window and cluster frame, avoid a second navigation, and detach on view/extension teardown. Do not implement a global native Back override as a consequence of this research.

## Supported navigation surface

`LensRendererExtension.navigate(pageId, params)` finds one of the extension's registered global/cluster pages, serializes its registered parameters and navigates to that route. `Renderer.Navigation.navigate(location)` is also public, along with details helpers and `isActiveRoute`; its implementation pushes to host observable history and compensates for duplicate current URLs. **Neither public surface exports a local-view stack or native Back interception registration.** [Extension registration/navigation](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/extensions/lens-renderer-extension.ts#L60-L131), [public navigation exports](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/extensions/renderer-api/navigation.ts#L47-L56), [navigate implementation](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/renderer/navigation/navigate.injectable.ts#L17-L35)

The host top-bar Back requests a window action, and main handles that action on the **focused BrowserWindow**. Separately, the native Back menu iterates all webContents of type `window`. These are distinct source paths and neither calls an extension-local Back action. Their effect on joint root/iframe history still needs runtime verification. [Top-bar callback](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/renderer/components/layout/top-bar/top-bar-items/navigation-to-back/go-back/go-back.injectable.ts#L11-L14), [window handling](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/main/ipc/window.ts#L11-L24), [menu handling](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/features/application-menu/main/menu-items/view/go-back/go-back-menu-item.injectable.ts#L20-L26)

DOM `preventDefault()` cancels a cancelable default action; it does not stop listeners. `stopPropagation()` stops travel to later objects, while `stopImmediatePropagation()` also stops later listeners on the current object. Neither reverses work already performed. A root handler can precede body/window **bubble** handlers, but not window **capture** handlers. [DOM event dispatch and cancellation](https://dom.spec.whatwg.org/#interface-event)

Electron's `before-input-event` precedes page key events and can suppress both those events and native menu shortcuts. `setIgnoreMenuShortcuts()` is a host-level alternative. **Proposal:** do not modify either for this viewer's ordinary shortcuts; choose bindings and scopes that cooperate with the host. A documented Electron mechanism is not an extension-local interception contract. [Electron 41.10.0 webContents](https://github.com/electron/electron/blob/v41.10.0/docs/api/web-contents.md#event-before-input-event)

## Cross-platform candidate contract — proposals for review

`Primary` means **Ctrl on Linux/Windows, Cmd on macOS**, matching Electron's `CommandOrControl`. In DOM code, select the platform's modifier; do not indiscriminately accept `ctrlKey || metaKey`. Electron maps Meta/Super to the Windows key outside macOS, which is not the intended local modifier. [Electron 41.10.0 modifier mapping](https://github.com/electron/electron/blob/v41.10.0/docs/tutorial/keyboard-shortcuts.md#cross-platform-modifiers)

| Action | Linux / Windows candidate | macOS candidate | Proposed ownership and exceptions |
| --- | --- | --- | --- |
| Find in retained logs | Ctrl+F | Cmd+F | Only active Readable logs **log-reading context**, including its toolbar, log viewport and inspector. Reveal/focus Find. Exclude Profiles, recovery dialogs, native dock, host sidebar, modal/menu and unrelated editable controls. The Find input itself is an explicit editable exception. |
| Next / previous matching record | Enter / Shift+Enter in Find | Return / Shift+Return in Find | Primary binding only while the **local Find input** is focused. Never reinterpret Enter in a draft, textarea, select, button, inspector content or host editor. Optional Primary+G / Primary+Shift+G may act while local Find is active and focus remains in the log-reading context; do not require F3. |
| Contextual close / local Back | Escape | Escape | One layer per press: owned popup/menu → local confirmation cancel → Find close → focused inspector close → Profiles return to logs. The exact inspector/Profiles graph remains a UX decision. When no local layer owns Escape, leave it alone. Never bind Escape globally to leave Readable logs or invoke host history. |
| Save profile draft | Ctrl+S | Cmd+S | Only an existing local draft inside Profiles. Invoke the same validation/save action as the visible Save button; consume within this context even when invalid, expose validation and retain the draft. Permit profile text fields as an explicit exception, but exclude nested modal/menu, IME composition and foreign embedded editors. No draft means no local Save command. |
| Additional keyboard Back | Optional Alt+Left | Use local Escape / visible Back; preserve Cmd+`[` | Alt+Left is only a candidate for an active local Profiles context after native validation; exclude editables and menus, never fall through to a synthetic host Back. Keep visible Back and Escape sufficient. Do not add Backspace or Option+Left as local Back. |
| To bottom | Ctrl+End | Cmd+Down | Only when the **log viewport itself or a log row** owns focus. Use the existing To bottom action, not a document-wide scroll. Exclude Find, inspector text, all editing controls and modifier variants that select text. Keep a visible button. |
| Mouse Back | Conditional button-3 path, or narrowly scoped native relay after proof | Unverified; no Electron app-command guarantee | Desired local Profiles return is retained as a requirement. No advertised cross-platform guarantee until the native gate passes. Pointer ownership matters: do not intercept a gesture over host/dock areas merely because Profiles is open. |

These are familiar candidates, not evidence of host support: Apple documents Cmd+F, Cmd+G/Shift+Cmd+G, Cmd+S and document-ending Cmd+Down; Microsoft documents Ctrl+F, Ctrl+End and Alt+Left; Chrome documents Ctrl+G/Shift+Ctrl+G on Windows/Linux. Text editing also uses several of these keys, which is why scope matters. [Apple, published 2026-09-14](https://support.apple.com/en-us/102650), [Microsoft, undated page](https://support.microsoft.com/en-us/accessibility/windows/keyboard-shortcuts-in-windows), [Chrome, undated page](https://support.google.com/chrome/answer/157179?hl=en)

### Focus and editable-control rules

The following are **proposed routing rules**, grounded in the observed host conflicts:

1. Install handlers only while the active view needs them; remove them on teardown. Require the active extension route/target, visible active local context, and focus in the owning region. A mounted/cached cluster frame is insufficient. Do not use Electron `globalShortcut` for any action here: it acts even when the app is unfocused. [Electron shortcut scopes](https://github.com/electron/electron/blob/v41.10.0/docs/tutorial/keyboard-shortcuts.md#global-shortcuts)
2. Resolve the topmost owned transient context before page navigation. Keep explicit popup/modal state; checking only the post-event DOM can miss a menu that an earlier capture handler just closed. For host/native menus, leave the command to the host and verify no second local action occurs.
3. Ignore composition and nonmatching modifier combinations. Use exact modifiers, reject AltGraph, and ignore held-key repeats for Save, Escape and Back so a single hold cannot save or dismiss several layers. UI Events defines `key`, physical `code`, repeat and composition state; keyboard layout affects key values. Prefer semantic `key` matching for labelled letter commands and test non-US layouts. [UI Events, Working Draft 2026-02-21](https://www.w3.org/TR/2026/WD-uievents-20260221/#interface-keyboardevent)
4. Default editable exclusions cover `input`, `textarea`, `select`, `contenteditable` ancestors and editor/widget-owned keyboard areas, including read-only selectable text. The explicit exceptions are Find commands in the local Find input and Save in local draft fields. Let a combobox, native select, autocomplete or IME consume Escape before considering navigation. Ordinary draft text fields may permit contextual Profiles Escape only when no such transient interaction owns it.
5. Consume only a matched command the local context owns, using cancellation and propagation control appropriate to its event phase. Honor `defaultPrevented`, but do not assume host handlers do. Avoid blanket document/window capture suppression and avoid `stopImmediatePropagation()` as a general fix.
6. Restore focus to the opener or nearest retained control after a local close. Keep Tab/Shift+Tab and native button Enter/Space behavior. The extension's current Find handles Enter/Shift+Enter, rows handle Enter/Space, and closing Profiles already focuses its opener; there is currently no extension Escape, Primary+F/S, mouse-Back or history handler. [Current viewer](https://github.com/maksimgurenko/freelens-json-logs/blob/f5c34068edc3be9386ce6bfec2f86a68bfe4a790/src/renderer/viewer.tsx#L141-L187)

The maintainer's established Profiles exit requirement is independent of the delivery mechanism: leaving Profiles discards its unfinished draft and retains saved changes; explicit Save remains the save action. This report does not decide a new confirmation or autosave policy. [Map #20 requirements, recorded 2026-10-24](https://github.com/maksimgurenko/freelens-json-logs/issues/20)

## Remaining native checks and decision consequences

These are **future verification gates**, not tests run here. Linux observations must not be presented as Windows/macOS acceptance.

| Gate | Required evidence |
| --- | --- |
| Physical mouse Back | On each supported OS and actual Electron version, record `mousedown`/`mouseup`/`auxclick` and pointer `button`/`buttons`, native app-command, root/cluster URLs, history state and any `popstate`. Test pointer over Profiles, native dock and host sidebar separately, with focus inside/outside the extension. Establish cancellation timing and whether one gesture causes both local and host navigation. Synthetic DOM events do not prove hardware delivery. |
| Native vs local Back | Profiles with/without draft, nested confirmation and a previously visited host page; repeat with top-bar Back, native menu Back, Ctrl/Cmd+`[`, Alt+Left, mouse Back and script history traversal. Verify the owning window/frame and ensure local Back never accidentally leaves the viewer. Decide separately whether host navigation is expected to discard the local draft. |
| Find competition | Native Logs tab/search mounted, text selected there, then focus returned to extension. Verify exactly one intended Find receives focus and no unintended native query changes. Repeat with native dock focus and inactive/cached cluster frames. |
| Escape arbitration | Menu/select/autocomplete/IME → confirmation → Find/inspector → Profiles. Verify a single press closes one intended context, restores focus and does not trigger host Drawer/SettingLayout/palette or a second action after a capture listener. |
| Save | Valid, invalid, unchanged and absent drafts; save failure; text-field/textarea focus; menu/modal; IME; held key. Verify saved work persists and rejected saves retain input without browser Save UI. |
| Modifiers and To bottom | Linux/Windows Ctrl and macOS Cmd; wrong/extra modifiers; AltGraph and non-US layouts; macOS Fn/function-key settings. Confirm caret motion and selection in editables, host dock shortcuts and OS shortcuts continue to work; To bottom affects only retained logs. |

If mouse Back cannot be scoped and consumed through the supported host boundary, report that constraint to the navigation decision ticket. Keep the visible local Back/Escape path and choose a documented upstream extension point or a separately approved host integration spike before promising native parity. The present research closes the factual investigation; it does not close the map's human navigation/shortcut decisions or those runtime gates.
