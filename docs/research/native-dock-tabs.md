# Readable logs in the native bottom dock

Researched on 2026-10-22. Scope: the bottom tab strip in the supplied screenshot (`Terminal`, `Pod changing-logs`, `Pod single-json`, and `+`), and Freelens **1.10.3**. This report records findings; it does not change the accepted specification.

**Answers:** (1) Joining that tab strip was **not** the agreed first-release behavior; the accepted interaction was a separate extension page opened from a Pod-header action. (2) Freelens 1.10.3's public extension API can open native log/terminal tabs, but it cannot register our React viewer as another native dock tab. Achieving that placement requires an upstream extension point or an unsupported integration with host internals/DOM. The evidence for each answer follows.

**Feasibility assessment:** a supported extension can open the same native Pod log tabs shown in the screenshot, with the native renderer. Hosting **our** viewer there is not supported in 1.10.3. A host fork/patch could add a custom registration/rendering path; a DOM/React interception could attempt to simulate the placement. Those are technical possibilities inferred from the host implementation, not verified integrations or supported public APIs. They also cross the current specification's prohibition on patching host internals. [Dock implementation](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/renderer/components/dock/dock.tsx#L107-L121), [accepted boundary](https://github.com/maksimgurenko/freelens-json-logs/issues/8#issuecomment-6352283620)

## Practical effect of changing the specification

For the currently accepted host/API boundary, retain the header action and separate page. If native dock placement becomes a requirement, first choose either an upstream public dock extension point and a host version that includes it, or explicitly accept maintaining a host-specific unsupported integration. Amend #6/#8's placement and integration boundary accordingly; a new dock requirement cannot be implemented merely by changing our page registration. [Accepted interactions](https://github.com/maksimgurenko/freelens-json-logs/issues/6#issuecomment-6351951935), [accepted implementation boundary](https://github.com/maksimgurenko/freelens-json-logs/issues/8#issuecomment-6352283620), [current registration surface](https://github.com/freelensapp/freelens/blob/3da74415bff57a77c6e08cb5f538191ce87bac17/packages/core/src/extensions/lens-renderer-extension.ts#L60-L78)

A revised contract should then decide whether opening another Pod creates a new tab or reuses one, what closing/reopening restores, and how inactive/minimized tabs suspend refresh. These are consequences to specify and validate, not decisions adopted by this report. The existing target identity, stale-result and hidden-view rules remain relevant. [Refresh/lifecycle contract #5](https://github.com/maksimgurenko/freelens-json-logs/issues/5#issuecomment-6331306075), [first-release lifecycle acceptance #8](https://github.com/maksimgurenko/freelens-json-logs/issues/8#issuecomment-6352283620)
