Readable logs 0.1.37 brings the extension to **Freelens 2**. It opens from a Pod's details header and keeps the bounded log viewer, formatting profiles, Find, and exact original-text copying.

- DEBUG and TRACE have distinct colors. Plain-text rows stay neutral in mixed snapshots.
- Profile and Inspection changes save through the main process. Confirmed settings recovery keeps an exact backup before replacing an unusable file.
- Find uses a main-process worker and waits for it to exit when the extension is disabled or Freelens quits.

## Install

Download **freelens-readable-logs-v2-0.1.37.tgz** and **SHA256SUMS** from this release's assets. Verify them in the same directory.

```sh
sha256sum --check SHA256SUMS
```

Open **Extensions** in a fresh Freelens 2 session before opening a cluster. If the old `freelens-readable-logs` entry is visible, uninstall it and keep its settings file. Install the v2 tarball and wait for **0.1.37 / Enabled**, then choose **Readable logs** in a Pod's details header.

The first v2 launch starts with built-in Default and Side inspection. New settings go to the `freelens-readable-logs-v2` store. The legacy settings file remains available. [Installation and settings guide](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.37/README.md#install)

## Compatibility

The package declares Freelens `^2.0.0`. The exact release archive passed
installed checks on official Freelens 2.0.0 Linux amd64. Windows and macOS
remain unverified. [Linux verification](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.37/docs/verification/freelens-2-linux-handoff.md#release-v0137)

Freelens 1.10.3 users can use the [0.1.36 release](https://github.com/maksimgurenko/freelens-json-logs/releases/tag/v0.1.36).
