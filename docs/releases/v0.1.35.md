Readable logs 0.1.35 adds the completed literal Find feature to **Freelens 1.10.3**.

- Search application text and extracted messages with Match case and Whole words, matching-record counts and wraparound navigation.
- See source-preserving highlights, scrollbar result marks and links to matches hidden from compact rows. Seed an empty query from selected log text and recall seven recent searches per view.
- Keep reading position and result identity across overlapping snapshots, query refinements and inspector layout changes. Pending work is cancelled when its navigation intent expires, with explicit search/highlight recovery controls.
- Use the compact black log workspace, scoped shortcuts and toggleable Inline, Side and Bottom inspection. Saved profiles, exact original-text copying, Pause/Resume and automatic refresh remain available.
- Includes the independently verified PR #49 fixes for query refinement after closing inspection, frame navigation during worker registration and unnecessary search restarts on layout-only changes.

## Install

Download **freelens-readable-logs-0.1.35.tgz** and **SHA256SUMS** from this release's assets. Verify them in the same directory:

```sh
sha256sum --check SHA256SUMS
```

Fully quit/reopen Freelens and open **Extensions before opening a cluster**. For an update, uninstall the old extension and wait for removal; saved settings are retained. Install the tarball once, wait for **0.1.35 / Enabled**, then open a cluster and choose **Readable logs** from a Pod's details. Do not use GitHub's source archives as the extension package.

See the [installation guide](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.35/docs/local-development.md#supported-local-maintenance) for the process-local filesystem polling used on the verified Linux setup. This version uses fresh main, renderer and worker filenames to avoid reusing cached modules from local 0.1.34 installations.

## Validation and accepted limits

The Find implementation completed [Linux acceptance](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.35/docs/verification/48/matrix.md) and [independent review with regression checks](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.35/docs/verification/48/pr-49-review.md). Those reports identify their tested commits and 0.1.34 artifacts; 0.1.35 updates release metadata and documentation without changing production behavior. Release CI runs TypeScript checks, 254 tests, the mounted production renderer, real worker cancellation/exit checks, resource smoke checks, package inspection and reproducible builds on the final versioned assets.

Windows/macOS validation is planned for a later task; both remain unverified. The Freelens watch-timer resource follow-up is closed as an accepted host limitation, with no production host patch or complete attribution of historical spikes; see the [specification TLDR and evidence](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.35/docs/design/find-implementation-plan.md#resource-investigation-tldr).

The viewer continues to retain at most 1,000 records and 5 MiB of original text for one Pod/container's current instance. It does not add streaming or multi-Pod aggregation.
