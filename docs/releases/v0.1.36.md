Readable logs 0.1.36 improves Find stability and aligns the toolbar with **Freelens 1.10.3**.

- Keep the active result and its ordinal when opening or closing its inspector. A single result stays `1 / 1`.
- Preserve the counter, scrollbar marks and hidden-match links on unchanged rows while refreshed logs are checked. Navigation waits for the complete result.
- Reuse matching results and highlight coverage for unchanged source text, preserve visible highlights during updates, and reduce work while scrolling long or wrapped records.
- Use compact Material icon controls, lighter container/profile selectors, and a Find field with its counter and clear button inside the input.

## Install

Download **freelens-readable-logs-0.1.36.tgz** and **SHA256SUMS** from this release's assets, then verify them together:

```sh
sha256sum --check SHA256SUMS
```

Fully quit/reopen Freelens and open **Extensions before opening a cluster**. Uninstall the previous extension and wait for removal; saved settings are retained. Install the tarball once, wait for **0.1.36 / Enabled**, then open a cluster and choose **Readable logs** from a Pod's details. GitHub's source archives are not installable extension packages.

See the [installation guide](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.36/docs/local-development.md#supported-local-maintenance) for the process-local filesystem polling used on the verified Linux setup.

## Validation and limits

The [verification report](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.36/docs/verification/releases/0.1.36/README.md) records the regressions, 259 tests, mounted production-renderer checks, and background checks of matching runtime sources installed in Freelens 1.10.3 on Linux. The installed checks used a local prerelease; final release filenames and embedded version strings differ. Release CI validates the final package, worker lifecycle, resource retention and reproducible bytes before publishing.

Windows and macOS remain unverified. This patch does not expand the existing 1,000-record / 5 MiB retained window or the supported-host and resource limits described in the [Find implementation plan](https://github.com/maksimgurenko/freelens-json-logs/blob/v0.1.36/docs/design/find-implementation-plan.md).
